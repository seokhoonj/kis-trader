# 한계·미구현

지원하는 조회·주문 표면은 [API 함수 트리](taxonomy.md)와 상품별 장에 정리돼 있습니다.
아래는 현재 구현의 제약과 주의사항이며 KIS 전체 API의 존재 여부를 판정하는 목록은 아닙니다:

| 기능 | 상태 | 비고 |
|---|---|---|
| **해외 선물·옵션 주문(매매)** | 지원(실전 전용) | `kis.overseas.futures(코드).buy()`/`sell()`. KIS가 모의투자를 제공하지 않아 **실전 계정에서만** 나갑니다 |
| **서버측 사전검사** (상하한가·주문가능·매도가능 KIS 검사) | 의도적 제외 | 발주 직전 상태는 변할 수 있음. `RiskLimits` 는 설정한 수량·금액·가격 편차·호가단위의 추가 보호이며 브로커의 현금·증거금·권한·접수 판단을 대체하지 않음 |

::: {.callout-note}
**퇴직연금**은 KIS 정책상 API 주문이 막혀 있어(IRP는 조회만, DC 가입자는 API 이용 불가) `kis.account.pension.*`
은 조회 전용입니다 — 패키지 한계가 아니라 KIS 제약입니다. **연금저축**(상품계좌 22)은 일반 국내 주문
경로(`kis.domestic.stock(...).buy()`)로 매매됩니다.
:::

## 요청 속도 제한 (throttle)

KIS는 앱키 단위로 초당 요청 수를 제한합니다([공식 FAQ](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000002/post/bcfb94ee-5aa3-4915-bca6-d63378c620c2): 실전 20/초, 모의 2/초). kis-trader는 **기본으로 스스로
속도를 제한**해 이 한도 아래로 요청을 흘립니다 — 여유를 둬 실전 15/초, 모의 1/초입니다.

- 필요하면 세션 생성 시 `KISClient(..., requests_per_second=…)` 로 조정하거나 `throttle=False` 로 끌 수 있습니다
  (끄면 한도 관리는 호출자 책임).
- **한도는 앱키 단위로 합산**됩니다. 같은 앱키를 다른 프로세스·도구가 동시에 쓰면 이 클라이언트가 아무리
  느리게 보내도 합산치가 한도를 넘어 **HTTP 500** 으로 떨어질 수 있습니다. 500이 뜨면 같은 앱키를 쓰는 다른
  실행이 없는지 확인하세요. 다만 HTTP500은 다른 서버 오류에서도 발생하므로 KIS 오류 메시지도
  함께 확인해야 합니다. 이 제한기는 다른 프로세스와 호출량을 공유하지 않습니다.
