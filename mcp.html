23  MCP 서버

23.1 MCP 가 처음이라면

MCP(Model Context Protocol) 는 AI 채팅 앱이 바깥의 도구나 데이터를 가져다 쓸 수 있게 해주는 표준 규격입니다. Anthropic 공식 문서는 이걸 AI 앱용 USB-C 단자에 빗댑니다 – USB-C 가 어느 기기든 꽂아 쓰는 공통 단자이듯, MCP 는 “계좌 조회 도구” 같은 걸 AI 앱에 꽂아 쓰게 해주는 공통 규격입니다.

어디에 쓰는지 보겠습니다. KIS 잔고를 확인하려면 보통 파이썬으로 이렇게 씁니다:

kis.account.balance()

MCP 를 켜 두면 Claude Desktop 채팅창에 이렇게 말하기만 하면 됩니다:

내 KIS 계좌 잔고 보여줘

그러면 에이전트가 알아서 balance 도구를 호출해 답해 줍니다. 코드를 치지 않고 대화만으로 계좌를 다룰 수 있다는 것, 그게 MCP 의 쓸모입니다.

구성은 두 조각입니다:

조각 무엇인가 여기서는
서버(server) 도구를 내주는 쪽. 내 PC 에서 돌며 KIS 와 통신합니다 kis-mcp(이 프로젝트가 제공)
클라이언트(client) 그 도구를 쓰는 AI 앱 Claude Desktop · Cursor · ChatGPT Desktop(참고)

둘은 MCP 규격으로 주고받습니다. 설정 파일에 서버를 한 줄 등록해 두면(아래 쓰는 법), 에이전트가 켜질 때 도구 목록을 받아 와 바로 씁니다.

노트

MCP 는 있어도 되고 없어도 되는 선택 기능입니다. 파이썬으로만 다룰 거면 필요 없습니다(import kis_trader 는 mcp 없이도 동작합니다). Claude Desktop 같은 AI 앱에서 대화로 계좌를 조회·확인하고 싶을 때만 켜면 됩니다.

23.2 쓰는 법 (설치하고 연결하기)

채팅창에서 뭘 내려받는 게 아닙니다. 아래를 한 번 해 두면, 그다음부터는 AI 앱 채팅창에서 말만 하면 됩니다. 설치는 세 앱(Claude Desktop·Cursor·ChatGPT Desktop)이 공통이고, 연결 방법만 앱마다 다릅니다 – 먼저 공통 설치를 끝내고, 쓰는 앱에 맞춰 아래 절 중 하나만 따라 하세요.

플랜·워크스페이스 정책에 따라 연결 가능 여부가 달라집니다. 현재 계정에서 다음 공식 안내와 서버 추가 메뉴를 확인한 뒤 연결하세요:

AI 앱 커스텀 MCP 플랜 조건
Claude Desktop 공식 로컬 MCP 안내와 설치된 앱의 MCP 설정·조직 정책 확인
Cursor 현재 MCP 안내와 계정의 플랜 조건 확인. Pro 이상만 가능하다고 가정하지 않음
ChatGPT Desktop 공식 연결 안내에서 현재 계정·워크스페이스 권한 확인
힌트

계좌 하나만 쓰는 가장 짧은 길은 가장 쉽게 시작 에 직선으로 정리돼 있습니다(Claude Desktop 기준). 거기서는 설정 블록을 kis config mcp 가 경로까지 채워 통째로 만들어 주므로 경로·JSON 을 직접 다룰 필요가 없습니다. 아래는 각 단계를 자세히 보고 싶거나 여러 계좌를 쓸 때의 전체 설명입니다.

노트

준비물 – 쓰려는 AI 앱 하나(Claude Desktop claude.ai/download, 또는 Cursor, 또는 ChatGPT Desktop)와 인터넷이면 됩니다. 설치 도구로 쓰는 uv 는 다음 단계에서 깔고, 파이썬이 없어도 uv 가 알아서 받아 주므로 파이썬을 미리 설치할 필요는 없습니다.

설치 (세 앱 공통)

1. 터미널(명령 입력창)을 엽니다. – macOS 는 ⌘ + Space 를 눌러 “터미널”을 검색해 실행, Windows 는 시작 메뉴에서 “PowerShell”을 실행합니다. 까만(또는 하얀) 글자 입력창이 뜹니다.

2. 설치 도구 uv 를 깔고 패키지를 설치합니다. – 아래를 순서대로 붙여넣고 Enter 합니다. 먼저 uv (이미 있으면 “already installed” 라고만 뜨고 넘어갑니다):

# macOS · Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

uv 를 처음 깔았으면 터미널을 새로 엽니다(PATH 반영). 그다음 패키지를 설치합니다:

uv tool install 'kis-trader[mcp]'
노트

pip 이 아니라 uv tool 을 쓰는 이유: 요즘 macOS 의 pip 은 막혀 있고(externally-managed-environment 오류), uv tool 은 실행 파일을 한 폴더에 모아 다음 단계에서 경로를 쉽게 찾을 수 있습니다 (uv tool dir --bin 으로 그 폴더를 확인). [mcp] 는 서버 실행에 필요한 의존성을 설치합니다. 실행 명령 자체는 기본 패키지에도 등록되지만, 의존성이 없으면 실행할 수 없으므로 따옴표째 그대로 붙여넣으세요.

3. 자격증명(앱키)을 저장합니다. – 터미널에 아래 한 줄을 치면 묻는 대로 입력합니다(앱키·시크릿은 화면에 보이지 않게 받습니다). 모의만 쓸 거면 실전 단계에서 그냥 Enter 로 건너뜁니다.

kis config

경우별 자세한 저장법(모의만·실전만·여러 계좌·계좌번호를 어디서 보는지)은 자격증명 설정 – 상황별 레시피 참고.

여기까지가 공통입니다. 이제 쓰는 앱에 맞춰 아래에서 하나만 따라 하세요.

23.3 Claude Desktop 에 연결

플랜: 공식 로컬 MCP 안내와 설치된 앱의 MCP 설정을 확인하세요. 조직 계정에는 관리자의 확장 프로그램 정책도 적용됩니다.

Claude Desktop 은 kis-mcp 를 stdio 로 직접 띄웁니다 – 설정 파일에 실행 파일 경로만 적으면 됩니다.

1. kis-mcp 경로를 확인합니다. – Claude Desktop 은 터미널 PATH 를 모를 수 있어 전체 경로로 적어 줍니다. 가장 확실한 건 다음 단계에서 쓸 kis config mcp 가 경로를 자동으로 채워 준 값이고, 직접 확인하려면 아래를 씁니다. uv tool install 로 깔았으면 경로는 보통 아래지만(나 는 사용자 이름), 환경에 따라 달라질 수 있으니 uv tool dir --bin 으로 실제 폴더를 확인하세요:

  • macOS · Linux: /Users/나/.local/bin/kis-mcp (Linux 는 /home/나/.local/bin/kis-mcp)
  • Windows: C:\Users\나\.local\bin\kis-mcp.exe

직접 확인하려면 which kis-mcp(macOS·Linux) 또는 where.exe kis-mcp(Windows PowerShell – 그냥 where 는 PowerShell 에서 다른 명령이라 안 됩니다; Get-Command kis-mcp 도 가능) 를 칩니다. 아무것도 안 나오면 설치가 안 됐거나 PATH 밖입니다 – 터미널을 새로 열어 공통 설치의 2단계를 다시 하세요.

2. Claude Desktop 설정 파일을 엽니다. – 전부 마우스로 합니다:

  1. Claude Desktop 의 설정(Settings) 을 엽니다 – macOS 는 화면 맨 위 메뉴 막대의 Claude → Settings…, Windows 는 왼쪽 위 메뉴(또는 설정 아이콘) → Settings. (채팅 창 안의 설정이 아닙니다.)
  2. 왼쪽에서 Developer 탭을 고르고, Edit Config 버튼을 누릅니다.
  3. 그러면 설정 파일(claude_desktop_config.json)이 열립니다. 없으면 자동으로 만들어 줍니다. (위치는 macOS ~/Library/Application Support/Claude/, Windows %APPDATA%\Claude\ 안입니다 – 버튼이 알아서 열어 주니 직접 찾아갈 필요는 없습니다.)

3. 아래 내용을 붙여넣고 저장합니다. – 파일 내용을 아래로 바꿉니다(파일이 비어 있거나 처음 만든 경우). 이미 다른 MCP 서버가 있으면 파일을 통째로 바꾸지 말고, 기존 "mcpServers" 안에 "kis-trader" 항목만 추가하세요(통째로 바꾸면 기존 서버가 지워집니다). command 에는 1단계에서 확인한 경로를, KIS_MCP_PROFILE 에는 저장한 프로필 이름(종합위탁이면 보통 general)을 넣습니다. OS에 맞는 쪽을 쓰세요 – 나 는 본인 사용자 이름으로 바꾸고, 모르면 1단계의 which/where 출력 줄을 그대로 복사해 넣으면 됩니다(Windows 는 역슬래시를 \\// 로). 저장은 ⌘ + S(Windows Ctrl + S).

macOS · Linux:

{
  "mcpServers": {
    "kis-trader": {
      "command": "/Users/나/.local/bin/kis-mcp",
      "env": { "KIS_MCP_PROFILE": "general", "KIS_MCP_ENVIRONMENT": "paper" }
    }
  }
}

Windows:

{
  "mcpServers": {
    "kis-trader": {
      "command": "C:\\Users\\나\\.local\\bin\\kis-mcp.exe",
      "env": { "KIS_MCP_PROFILE": "general", "KIS_MCP_ENVIRONMENT": "paper" }
    }
  }
}
중요

Windows 경로는 역슬래시(\)를 두 번(\\) 쓰거나 슬래시(/)로 바꿔야 합니다. where 가 준 C:\Users\... 를 그대로 붙여넣으면 JSON 이 깨져(백슬래시가 특수문자) 서버가 조용히 안 뜹니다 – 위 예처럼 C:\\Users\\...\\kis-mcp.exe 또는 C:/Users/.../kis-mcp.exe 로 적으세요.

모의 키를 안 넣었고 실전 키만 저장했다면 KIS_MCP_ENVIRONMENT 을 "real" 로 바꿉니다(실주문은 아래 실주문 가드레일을 추가로 갖춰야 열립니다). KIS_MCP_PROFILE 과 KIS_MCP_ENVIRONMENT 은 같은 환경 블록에 저장된 계좌를 가리켜야 합니다 – 저장하지 않은 조합을 가리키면 조회가 실패하니, 그때는 아래 연결 팁(HTTP 500 진단·로그 위치)을 보세요.

4. Claude Desktop 을 완전히 껐다 켭니다. – 창만 닫지 말고 완전히 종료(macOS ⌘ + Q, Windows 는 트레이 아이콘에서 종료)한 뒤 다시 실행합니다. 설정은 켤 때 한 번만 읽습니다.

5. 연결됐는지 봅니다. – 채팅 입력창 왼쪽 아래의 +(파일·커넥터 추가) 아이콘을 누르고 Connectors → Manage connectors 로 가면 kis-trader 와 그 도구들이 보입니다. 보이면 성공입니다.

6. 이제 채팅창에서 말만 하면 됩니다. – “삼성전자 현재가 알려줘”, “내 KIS 잔고 보여줘”처럼 말하면 Claude 가 알아서 해당 도구를 불러 답합니다.

힌트

프로필(KIS_MCP_PROFILE)로 붙이는 걸 권합니다. 설정 파일에 KIS_APP_KEY·KIS_APP_SECRET 을 직접 적는 대신, 저장소(~/.config/kis-trader/credentials.json)에 둔 프로필 이름만 적으면 앱키가 설정 파일에 드러나지 않습니다. KIS_MCP_PROFILE 은 계좌 종류(general·isa·pension·irp), KIS_MCP_ENVIRONMENT 은 환경(real/paper)으로 서로 다른 축입니다 – 둘이 같이 그 환경 블록에 저장된 계좌 종류를 가리켜야 하며(예 general+paper), 저장하지 않은 조합(예: 모의 키만 넣고 real 을 고름)을 가리키면 조회가 HTTP 500(“Error executing tool”) 으로만 실패할 수 있습니다 – 원인 메시지가 화면에 안 보이니, 그때는 로그를 보세요: macOS ~/Library/Logs/Claude/mcp-server-kis-trader.log, Windows %APPDATA%\Claude\logs\mcp-server-kis-trader.log. 환경은 기본이 모의(paper)이고, 실전은 아래 KIS_MCP_ENVIRONMENT=real 로 선택합니다. 실전 계좌 조회와 실전 주문 권한은 별개이며, 실전 주문 도구를 사용하려면 실주문 가드레일이 추가로 필요합니다.

(선택) 서버가 잘 뜨는지 터미널에서 점검하기

연결이 안 되면 서버가 혼자 잘 뜨는지 확인해 볼 수 있습니다. 자격증명을 환경변수로 주고 kis-mcp 를 실행합니다 – kis-mcp 는 공통 설치 2단계에서 깐 명령으로, 이 줄이 서버를 띄웁니다.

# macOS · Linux
export KIS_APP_KEY=...
export KIS_APP_SECRET=...
export KIS_ACCOUNT=...
export KIS_MCP_ENVIRONMENT=paper  # 실전은 real (명시할 때만)

kis-mcp  # 서버 시작. 오류 없이 뜨면 정상 -- 연결을 기다리며 멈춰 있고, Ctrl-C 로 끕니다.
# Windows (PowerShell) -- export 가 아니라 $env: 로 설정합니다
$env:KIS_APP_KEY="..."
$env:KIS_APP_SECRET="..."
$env:KIS_ACCOUNT="..."
$env:KIS_MCP_ENVIRONMENT="paper"  # 실전은 real (명시할 때만)

kis-mcp  # 서버 시작. 오류 없이 멈춰 있으면 정상 -- Ctrl-C 로 끕니다.

오류 없이 멈춰 있으면 정상입니다. 이건 “제대로 뜨는지”만 보는 점검용이라, 이 상태로 사람이 직접 대화할 수는 없습니다. 실제 사용에선 이 줄을 직접 칠 일이 없고, 위 순서대로 Claude Desktop 이 kis-mcp 를 대신 띄워 줍니다.

23.4 Cursor 에 연결

플랜: 현재 계정의 MCP 지원 조건을 확인하세요. 공식 기존 플랜 안내에는 Pro 외 Start에도 MCP가 포함돼 있습니다. 현재 계정에 적용되는 조건은 위 안내와 앱 설정에서 확인하세요.

Cursor도 stdio를 지원합니다. 공식 수동 설정 안내에 따라 프로젝트의 .cursor/mcp.json 또는 사용자 전체 설정인 ~/.cursor/mcp.json 에 위 Claude Desktop 등록 JSON의 mcpServers 항목을 기존 설정과 병합합니다. command 에는 kis-mcp 전체 경로를 넣고, 저장한 뒤 Cursor를 다시 시작합니다.

(고급) 전송 방식 바꾸기 – stdio · sse · streamable-http

기본 전송은 stdio 입니다 – Claude Desktop·Cursor 는 이걸로 서버를 직접 띄워 씁니다. 한 서버에 여러 클라이언트를 붙이거나 mcp-remote 같은 브리지를 쓸 때는 KIS_MCP_TRANSPORT 로 HTTP 계열 전송을 고릅니다.

KIS_MCP_TRANSPORT 전송 엔드포인트(기본)
stdio(기본) 표준 입출력 (클라이언트가 직접 실행)
sse HTTP Server-Sent Events http://127.0.0.1:8000/sse
streamable-http HTTP(스트리밍) http://127.0.0.1:8000/mcp 
export KIS_MCP_TRANSPORT=streamable-http  # 또는 sse
export KIS_MCP_HOST=127.0.0.1             # bind host (기본 127.0.0.1, 로컬 전용)
export KIS_MCP_PORT=8000                  # 기본 8000
kis-mcp

기본은 로컬(127.0.0.1) 전용입니다. 돈이 오가는 서버라, 토큰 없이 비-로컬 host 로 열려 하면 거부합니다 (fail-closed). 공개 HTTPS로 연결할 때는 아래 보호를 갖추세요. ChatGPT의 Secure MCP Tunnel을 사용하는 경우에는 터널의 로컬 대상과 인증 구성을 공식 안내에 따라 별도로 설정합니다.

  1. KIS_MCP_ACCESS_TOKEN 을 설정하면 비-로컬 bind 가 열리고, 모든 HTTP 요청에 Authorization: Bearer <토큰> 을 요구합니다(불일치/누락 → 401). 방어심층입니다.
  2. 그 앞에 TLS·인증(OAuth 등)을 맡는 역프록시/터널(Cloudflare Tunnel+Access, oauth2-proxy 등)을 두어 127.0.0.1 로 띄운 서버로 전달하는 것이 권장 방식입니다. bind host 는 KIS_MCP_HOST(기본 127.0.0.1)로 바꾸며, 공개 host 로 직접 bind 한다면 KIS_MCP_ALLOWED_HOSTS(쉼표 구분, 예 my.host:*)로 허용 Host 를, KIS_MCP_ALLOWED_ORIGINS(쉼표 구분)로 허용할 CORS Origin 을 지정하세요.

실주문은 전송 방식과 무관하게 사람 확인(elicitation) 게이트를 그대로 거칩니다 – 원격이라고 느슨해지지 않습니다.

23.5 (참고) ChatGPT Desktop 에 연결

중요

연결 가능 여부는 현재 ChatGPT 계정·워크스페이스 정책을 확인하세요. 아래 절차는 공식 연결 안내의 사용자 지정 MCP 서버 연결을 기준으로 하며, 특정 개인 플랜이나 워크스페이스의 사용 권한을 보장하지 않습니다.

ChatGPT에는 공개 HTTPS의 streamable HTTP 서버(/mcp)나 Secure MCP Tunnel로 연결합니다. 터널은 설정한 로컬 stdio 또는 HTTP MCP 서버에 연결할 수 있습니다. SSE만 요구되는 것은 아닙니다. 공개 인터넷에 직접 노출하지 않을 로컬 HTTP 예시는 다음과 같습니다:

export KIS_MCP_PROFILE=general
export KIS_MCP_ENVIRONMENT=paper
export KIS_MCP_TRANSPORT=streamable-http
kis-mcp  # 기본 loopback 주소의 /mcp 경로

loopback HTTP는 토큰 없이 시작할 수 있습니다. 비로컬 주소에 직접 바인딩하려면 KIS_MCP_ACCESS_TOKEN 이 필요하며, 토큰을 설정하면 loopback에서도 인증을 검사합니다. 공개 URL 운영 시 TLS·인증·접근 제어를 별도로 갖추세요. 앞 절의 SSE 설정은 서버가 지원하는 다른 전송 옵션이며 ChatGPT 연결의 필수 조건은 아닙니다.

  1. chatgpt.com/plugins 에서 추가 버튼 → Add custom MCP server를 선택합니다.
  2. 이름·설명을 입력하고 Connection에서 공개 /mcp URL 또는 Tunnel을 선택합니다. 터널은 공식 안내에 따라 로컬 stdio/HTTP 서버를 대상으로 먼저 구성해야 합니다.
  3. 인증과 위험 안내를 확인한 뒤 Create as a plugin을 선택하고 발견된 도구·메타데이터를 검토합니다.
  4. 연결된 뒤 조회부터 확인하세요. 주문 도구는 아래 별도 안전장치가 적용됩니다.

안전: kis-mcp 는 조회·주문 미리보기·대조에 더해 실주문 도구(place_order·cancel_order·modify_order)도 내주지만, 실주문은 기본 차단입니다 – 기동 시 명시적 언락 환경변수(KIS_MCP_ALLOW_REAL + KIS_MCP_REAL_CONFIRM)와 real 환경이 모두 갖춰지고 사람 확인을 거쳐야만 전송됩니다(기본은 paper, 안전 설계). HTTP 로 열 때도 비-로컬 bind 는 KIS_MCP_ACCESS_TOKEN 없이는 거부되고(fail-closed), 토큰 불일치 요청은 401 로 막힙니다. 공개 URL 로 직접 bind 하기보다 Secure MCP Tunnel 또는 역프록시를 쓰는 편이 안전합니다(자세한 env 설정은 위 (고급) 전송 방식 바꾸기 항목).

23.6 이 서버가 하는 일

kis_trader.mcp 는 KIS 계좌를 MCP 도구로 내주는 서버입니다. kis_trader 의 공개 API(안전 코어) 위에 얹힌 얇은 계층이라 스스로 계산하지 않습니다 – 숫자는 전부 패키지가 만들고, 이 서버는 그걸 도구로 전달만 합니다.

중요

실주문(매수·매도·정정·취소)은 기본이 모의(paper)이고, 실전 주문은 여러 겹의 안전장치를 모두 통과해야만 나갑니다 – 이중 잠금 + fat-finger 한도(RiskLimits) + 종목 허용목록(allowlist) + 사람 확인(elicitation) + 세션 서킷브레이커(아래 실주문 가드레일). 하나라도 빠지면 주문을 보내기 전에 막습니다 (fail-closed; 도구별 예외는 아래 적용 범위 참고). 주문 내용(종목·매수매도·수량·가격)은 확인 창에서 사람이 직접 검토해야 합니다. 스칼라 인자만 받는 형식이 입력의 사람 작성 여부나 조회 결과에서 유래했는지까지 추적·보장하지는 않습니다.

23.8 계좌·환경 전환 (채팅에서)

활성 계좌·환경을 채팅에서 바로 바꿀 수 있어, config 를 고치고 Claude Desktop 을 재시작할 필요가 없습니다. KIS_MCP_PROFILE·KIS_MCP_ENVIRONMENT 는 기동 시 초기값일 뿐입니다.

도구 말투 하는 일
use_environment("real") / ("paper") “실전으로 바꿔줘” 활성 환경을 토글(언락 비트는 기동 시 고정)
use_profile("pension") “연금 계좌로 바꿔줘” 활성 계좌 종류 변경(조회·주문 대상 함께; general/isa/pension/irp)
list_profiles() “바꿀 수 있는 계좌를 보여줘” 활성 환경의 저장·전환 가능 프로필 + 활성 프로필·환경·switching_enabled(false 면 빈 목록)
current_account() “지금 뭐 보는 중?” 활성 (계좌 종류, 환경) + 마스킹 계좌

전환은 활성 (계좌 종류, 환경) 맥락을 바꿀 뿐, 기동 시 정해진 실주문 언락 비트는 바꾸지 못합니다 (위 callout 참고). 없는 조합(예 모의가 없는 pension 을 paper 로)이나 지원하지 않는 계좌(파생은 use_profile 대상 아님)는 전환 시점에 분명한 에러로 거부합니다(silent 전환 없음).

중요

환경을 real 로 바꾸는 것 자체는 실주문 언락 비트를 바꾸지 못합니다. 실주문 권한은 기동 시 준 가드(아래 실주문 가드레일)에만 묶입니다. 하지만 서버가 기동 시 KIS_MCP_ALLOW_REAL=1 + KIS_MCP_REAL_CONFIRM=i-understand-real-money 와 함께 떠 있었다면, KIS_MCP_ENVIRONMENT=paper 로 기동했더라도 use_environment("real") 뒤에는 실주문이 나갈 수 있습니다(사람 확인·RiskLimits·종목 허용목록은 여전히 적용). 실주문 의도가 없으면 기동 시 KIS_MCP_ALLOW_REAL 을 설정하지 마십시오 – 그러면 환경을 real 로 바꿔도 실주문은 끝까지 막힙니다. 국내 주문은 주문 가능한 주식 계좌(위탁·ISA 는 상품코드 01, 연금저축은 22)에서 나가고, IRP(29)·파생은 조회 전용이라 주문이 나가지 않습니다. 해외 주문(region="overseas")은 위탁(general) 계좌 전용입니다.

23.9 안전 설계

  • 실주문은 안전장치를 거친 뒤에만 – place_order·cancel_order·modify_order 는 아래 안전장치를 거친 뒤에만 나갑니다(도구별로 적용되는 겹이 다릅니다 – 적용 범위 참고). order_preview 는 아무것도 전송하지 않지만, 주문 형상 검증에 더해 발주와 동일한 계좌 권한 게이트 와 해외 실주문 통화별 금액 한도 사전점검을 적용합니다. 다만 실주문 언락·사람 확인·서킷브레이커는 발주 경로에서만 수행하며 preview 에는 없습니다.
  • 정보 유출 차단 – 응답은 frozen dataclass 에서 공개 필드만 골라 직렬화하고, _raw(벤더 원본 응답)와 밑줄 필드는 떼어 냅니다. 계좌번호는 마지막 4자리만 남기고 가립니다(****7801). 자격증명은 환경변수 또는 KIS_MCP_PROFILE 로 지정한 저장 프로필에서만 읽고 절대 출력하지 않습니다.
  • 기본은 모의 – 환경은 기본이 모의투자입니다. 실전 계좌 조회는 KIS_MCP_ENVIRONMENT=real 로 선택하며, 이중 잠금은 실전 주문 도구의 전송 권한에 추가로 필요합니다.
  • 계좌 종류에 맞는 조회 – balance·positions 는 활성 계좌 종류로 분기합니다(위탁·ISA·연금저축은 국내주식, IRP 는 퇴직연금). 해외주식 잔고·보유는 region="overseas" 로 보며, 위탁(general) 계좌의 실전 전용입니다(모의 미지원). open_orders(정정취소가능주문조회)는 주문 가능한 국내주식 계좌(위탁·ISA·연금저축) 전용이고 IRP 는 거부되며, 그 밖의 계좌에서는 분명히 거부합니다. 파생 계좌는 조회조차 노출하지 않습니다. MCP balance 는 (위탁 계좌에서) 국내주식 잔고를 돌려줍니다 – 국내·채권·해외를 합친 통합 잔고가 필요하면 파이썬 API kis.account.balance() 를 씁니다.

23.10 실주문 가드레일

실전(real) 주문은 아래 모든 겹을 통과해야 나갑니다(모의는 돈이 오가지 않아 대부분 건너뜁니다). 하나라도 어긋나면 주문을 보내기 전에 막습니다(fail-closed).

도구별 가드 적용 범위

세 실주문 도구가 같은 겹을 전부 거치는 것은 아닙니다 – 취소는 노출을 줄이는 동작이라 fat-finger 한도·허용목록을 적용하지 않고, 서킷브레이커 슬롯도 쓰지 않으며 HALT 상태에서도 막히지 않습니다 (위험한 주문을 빠져나오지 못하게 막는 것이 더 위험하므로 – HALT 중에도 취소는 나갑니다).

도구 이중 잠금 RiskLimits 종목 허용목록 사람 확인 서킷브레이커
place_order O O O (주문 종목) O O
modify_order O O O (원주문 종목; 저장소에서 해석될 때) O O
cancel_order O – – O – (HALT 중에도 취소 가능)

modify_order 의 허용목록은 원주문 종목으로 확인합니다(정정은 재가격·수량으로 노출을 늘릴 수 있어 신규 주문과 같은 종목 통제를 받습니다). 원주문을 저장소에서 찾지 못하면 허용목록 확인은 건너뛰고 나머지 게이트(이중 잠금·RiskLimits·사람 확인·서킷브레이커)는 그대로 적용합니다. 정정/취소 사람 확인 티켓에는 원주문 종목·매수/매도가 함께 표시됩니다.

실전 주문을 켜려면 이 값들을 쓰는 법에서 만든 설정 파일의 같은 env 블록에 넣습니다 – Claude Desktop 이 서버를 그 설정으로 띄우기 때문에, 터미널에서 친 export 는 그 프로세스까지 닿지 않습니다. JSON 이라 값은 전부 문자열로 적습니다.

{
  "mcpServers": {
    "kis-trader": {
      "command": "/Users/나/.local/bin/kis-mcp",
      "env": {
        "KIS_MCP_PROFILE": "general",
        "KIS_MCP_ENVIRONMENT": "real",
        "KIS_MCP_ALLOW_REAL": "1",
        "KIS_MCP_REAL_CONFIRM": "i-understand-real-money",
        "KIS_MCP_MAX_ORDER_QTY": "100",
        "KIS_MCP_MAX_ORDER_NOTIONAL": "10000000",
        "KIS_MCP_MAX_ORDER_NOTIONAL_USD": "10000",
        "KIS_MCP_SYMBOL_ALLOWLIST": "005930,000660"
      }
    }
  }
}

터미널에서 kis-mcp 를 직접 띄울 때만 같은 값을 export KIS_MCP_ALLOW_REAL=1 식으로 줍니다.

하나라도 빠지면 그 종목의 실주문은 거부됩니다(fail-closed). 손실은 전액 계좌 보유자 책임입니다.

23.11 설치는 선택 묶음

mcp 는 선택 의존성입니다 – import kis_trader 자체는 mcp 없이도 동작하고, MCP 서버를 쓸 때만 uv tool install 'kis-trader[mcp]' 로 설치하면 됩니다(위 쓰는 법 참고).

실주문은 위 실주문 가드레일을 거쳐 place_order 로 나갑니다. 국내 주식의 지정가· 시장가와 division 주문구분(조건부지정가 등), 그리고 region="overseas" 해외주식 지정가 주문이 place_order 로 되지만, 그 밖의 주문(파생·채권·스톱(조건가) 등)은 아직 MCP 에 없으니 주문의 파이썬 API 로 사람이 직접 냅니다.

23.12 면책 · 책임 (꼭 읽어주세요)

이 MCP 서버는 실제 돈이 오가는 증권 계좌를 AI 에이전트가 다루게 합니다. 안전장치를 겹겹이 뒀지만, AI 에이전트로 주문한다는 것 자체에 다음과 같은 본질적 위험이 있습니다 – 모두 이해하고 쓰세요.

  • 에이전트는 말을 오해할 수 있습니다. 자연어를 해석해 도구를 부르므로 의도와 다른 종목·수량·가격으로 주문할 수 있습니다. 실전에서는 전송 전 사람 확인(elicitation) 창의 내용을 반드시 직접 검토하고 맞을 때만 승인하세요 – 자동 승인하지 마세요.
  • 프롬프트 인젝션 위험. 에이전트가 읽는 내용(뉴스·시세·웹·문서)에 악의적 지시가 숨어 에이전트를 조종해 원치 않는 주문을 유도할 수 있습니다(이른바 lethal trifecta). 이 서버는 주문 파라미터의 출처를 자동 추적하지 않습니다. 악의적 내용이나 모델 오류가 주문 확인 창에 반영될 수 있으므로 allowlist·사람 확인·금액 상한으로 위험을 줄이고 확인 창을 직접 검토해야 합니다.
  • 가드레일은 위험을 “줄이는” 장치이지 “보장”이 아닙니다. 이중 잠금·RiskLimits·allowlist·사람 확인· 서킷브레이커는 실수와 오용을 어렵게 만들 뿐, 버그·오설정·예기치 못한 경로로 잘못된 주문이 나갈 가능성을 0으로 만들지는 못합니다.
  • 체결은 되돌릴 수 없습니다. 접수와 체결은 다르며, 남은 주문의 정정·취소 가능 여부는 현재 상태에 따라 달라집니다. 손익 실현·정산·출금 가능 시점은 거래와 브로커 기준으로 확인하세요.
  • 원격 노출은 운영자 책임. 서버를 네트워크에 열면(ChatGPT 등) 돈이 오가는 엔드포인트가 노출됩니다 – TLS·인증·접근 통제는 서버를 띄운 사람의 책임입니다.

책임 소재. 이 소프트웨어는 비공식 오픈소스이며 “있는 그대로(AS-IS)” 무보증으로 제공됩니다(MIT 라이선스). 이 서버의 사용(에이전트가 대신 낸 주문을 포함한 실주문·조회)으로 발생한 모든 금전적 손실· 주문 오류·데이터 오류·오작동에 대한 책임은 전적으로 계좌 보유자 본인에게 있으며, 제작자는 어떠한 책임도 지지 않습니다. 에이전트가 사용자를 대신해 낸 주문도 사용자가 낸 주문으로 간주됩니다.

실거래 전 반드시 모의투자(paper)로 충분히 연습하고, 실전은 소액·좁은 allowlist·낮은 한도로 시작하세요.
